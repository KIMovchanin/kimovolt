# Архитектура KIMOVOLT LAB

## 1. Общая схема системы

Платформа построена как монорепозиторий из четырёх чётко разделённых слоёв:

```text
[ React 19 UI + SVG Workbench ] <── postMessage ──> [ Web Worker: @kimovolt/simulation ]
             │
             ├── localStorage (гостевой режим / автономная работа)
             └── REST JSON + HttpOnly Session ──> [ Go 1.26 Binary + modernc.org/sqlite (WAL) ]
```

### Принципы разделения ответственности

1. **Математика изолирована от UI (`simulation/`):**
   Пакет `@kimovolt/simulation` не зависит от браузерного DOM или React. Он исполняется внутри Web Worker (чтобы не блокировать отрисовку интерфейса) и в Node/Vitest для детерминированного модульного тестирования.
2. **Декларативная образовательная модель (`content/`):**
   Схема `Track → Module → Lesson (version) → Step → Exercise` описана данными. Валидаторы упражнений обращаются напрямую к `@kimovolt/simulation` и проверяют физические инварианты (ток, напряжение, поведение при переключении ключей, полные таблицы истинности), а не расположение компонентов на экране.
3. **Клиентский редактор (`frontend/`):**
   Реализован на нативном SVG/Canvas без тяжёлых сторонних UI-фреймворков. Дизайн-система использует CSS custom properties + `<meta name="color-scheme">` с поддержкой тёмной темы (`Obsidian Dark` по умолчанию) и светлой чертёжной темы (`Blueprint Light`).
4. **Монолитный однобинарный бэкенд (`backend/`):**
   Написан на Go 1.26 (стандартный `net/http` с шаблонами маршрутизации Go 1.22+, `log/slog`, `modernc.org/sqlite` без CGO). Статические ассеты `frontend/dist` и API обслуживаются одним процессом за Caddy.

## 2. Формат хранения схем и версионирование

- Каждый документ схемы соответствует `CircuitDocumentSchema` (`schemaVersion: 1`).
- Импорт сторонних JSON-файлов (`.kimovolt.json`) проходит через `parseAndValidateCircuitJson()`:
  - лимит размера файла `256 KB`;
  - защита от загрязнения прототипа (`__proto__`, `constructor`, `prototype`);
  - строгая валидация схемой Zod (не более `200` компонентов и `500` проводов).
- Каждый урок имеет номер версии `version` (`uint >= 1`), чтобы обновления учебного текста не разрушали сохранённый прогресс пользователя.

## 3. Хранение данных и синхронизация

- **Гостевой режим:** все результаты шагов, Mastery навыков, расписание интервальных повторений (SRS), достижения, заметки блокнота и схемы хранятся в `localStorage`.
- **Аккаунт:** при регистрации или входе клиента выполняется `POST /api/v1/sync/migrate-guest`, объединяющий гостевые достижения, максимальные значения XP/Mastery, заметки и сохранённые схемы с серверной БД SQLite без потери данных.
- **Отказоустойчивость:** если сервер синхронизации временно недоступен, приложение выводит ненавязчивое уведомление, но продолжает локально работать в уроках и лаборатории.
