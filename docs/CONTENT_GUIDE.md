# Руководство по созданию контента (`content/`)

Все уроки, справочник, проекты и навыки описаны декларативно в `content/src/data/`.

## 1. Структура урока (`LessonDefinition`)

```text
Track -> Module -> Lesson (version >= 1) -> Step -> Exercise
```

Каждый урок следует методическому циклу:
1. `observe` — наблюдение и формулировка проблемы;
2. `predict` — прогноз результата ДО эксперимента;
3. `experiment` — управление параметром на живой модели;
4. `measure` — снятие показаний приборами (мультиметр/осциллограф);
5. `explain` — физическое объяснение и точные границы упрощений;
6. `apply` — самостоятельная сборка, ремонт неисправности или инженерная спецификация.

## 2. Типы проверяемых заданий (`validators.ts`)

- `multiple_choice` / `predict_outcome` / `component_recognition`
- `numeric` (с допуском `%` и парсингом SI-единиц RU/EN)
- `resistor_color_code` (декодирование и выставление 4 цветовых полос)
- `tune_parameter` (проверка рабочего тока/напряжения в MNA + опциональный стандарт E12)
- `build_circuit` (топология и MNA-инварианты, включая проверку обхода выключателей)
- `find_fault` / `unknown_circuit_diagnosis` (проверка полного устранения неисправности)
- `measure_multimeter` (режим, точки подключения щупов и снятое значение)
- `oscilloscope_analysis` (период, частота, амплитуда, Duty Cycle)
- `logic_circuit` (проверка всей таблицы истинности 2^k)
- `engineering_spec` (программный перебор всех комбинаций кнопок в MNA)

## 3. Проверка технической корректности

После добавления или правки уроков обязательно запускайте:
```powershell
npm.cmd test --workspace=content
```
Тест проверяет уникальность ID, отсутствие циклов в пререквизитах, паритет ключей RU/EN и физическую решаемость всех схем в уроках и проектах.
